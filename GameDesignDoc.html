🎮 Przegląd projektu

Ratocalypse 2.5 to izometryczne RPG akcji (single player) w stylu Diablo osadzone w postapokaliptycznym świecie zdominowanym przez zmutowane szczury. Sterowanie klawiatura i mysz (click-to-move). Warunek zwycięstwa: ukończenie głównego wątku fabularnego. Warunek porażki: spadek HP gracza do 0.

Gatunek

Izometryczne RPG akcji (Diablo-like). Widok z góry pod kątem, sterowanie click-to-move przez NavMesh.

Silnik i render

Unity 6000.4.3f1, Universal Render Pipeline (URP) 17.4.0.

Platforma docelowa

PC (Windows).

Kluczowe zależności

Cinemachine 3.1.6 · Input System 1.19.0 · FMOD · AI Navigation 2.0.12 · TextMeshPro

Główna pętla rozgrywki

  1. Eksploracja — gracz porusza się po arenie, odkrywa obszary
  2. Walka — wykrycie i eliminacja wrogów, zdobywanie XP
  3. Zbieranie — podnoszenie przedmiotów, realizacja questów
  4. Progresja — level up, wydawanie punktów umiejętności, ulepszanie ekwipunku

Przejście między etapami: wrogowie spawnują w obszarach, quest wymaga znalezienia itemu → wróć do NPC → XP reward → level up.

🏗️ Architektura i wzorce

EventBus — globalny system zdarzeń

Cały projekt komunikuje się przez EventBus oparty na typach (struct jako zdarzenia — zero alokacji na stercie). Żaden system nie trzyma bezpośredniej referencji do innego — wszystko przez zdarzenia. Każdy subskrybent wywołuje Unsubscribe w OnDisable.

PlayerHealthComponent → OnPlayerDamaged → PlayerHUD (aktualizuje pasek HP) PlayerHealthComponent → OnPlayerStaminaChanged → PlayerHUD (aktualizuje pasek staminy) EnemyAI → OnEnemyDied → XPSystem (przyznaje XP) QuestManager → OnQuestCompleted → XPSystem (przyznaje XP za questa) InventorySystem → OnInventoryChanged → QuestManager (sprawdza czy item questa w plecaku) SkillTreeManager → OnSkillUnlocked → SkillTreeUI (odświeża węzły)

ScriptableObject jako dane (DTO)

Dane gry trzymane są w ScriptableObject assetach — nie w scenach. Każdy typ wroga, przedmiotu, questa, umiejętności to osobny asset. Pola SO są read-only w runtime (Z2). Definicje umiejętności: SkillDefinitionSO + rejestr SkillRegistrySO.

Wzorce architektoniczne

  • Singleton:GameManager, QuestManager, MinimapController, AudioManager — dostępne globalnie przez .Instance
  • Interfejsy:IDamageable (IsAlive, TakeDamage(DamageInfo)), IHealable (Heal), IInteractable — obiekty oddziałują przez interfejs, nie twardą referencję (Z4)
  • FSM:EnemyAI jako Finite State Machine (Patrol / Alert / Chase / Attack / Stunned / Dead)
  • Component per responsibility:Jeden skrypt = jedna odpowiedzialność. PlayerController (ruch), PlayerCombat (walka), PlayerHealthComponent (HP/Stamina) — osobne komponenty na tym samym GameObject.
  • DamageInfo:Niezmienna struktura (readonly struct) przekazywana przez IDamageable.TakeDamage(). Niesie: wartość, typ, flagę krytu, kierunek odrzutu, źródło.

🧍 System gracza

Ruch — click-to-move (MOV-001)

Gracz porusza się klikając lewym przyciskiem myszy na cel w scenie. Silnik ruchu to NavMeshAgent z AI Navigation 2.0.12. Prędkość ruchu: PlayerStats.TotalMoveSpeed (baza 5 m/s). Zasięg interakcji: 2 m. Zasięg ataku: 1,5 m. Prędkość aktualizowana automatycznie po zmianie ekwipunku lub awansie.

Priorytet kliknięć

Klik LPM ↓ Warstwa Interactable / NPC? → podejdź (≤ 2 m) i wywołaj IInteractable.Interact() ↓ nie Warstwa EnemyLayer? → ustaw CurrentTarget, podejdź i atakuj ↓ nie Warstwa GroundLayer → idź do punktu, CurrentTarget = null

Unik (MOV-002)

Shift + PPM — dostępny gdy stamina ≥ 25 pkt. Parametry:

  • Koszt staminy:25 pkt
  • Prędkość uniku:12 m/s
  • Czas trwania:0,3 s

Podczas uniku aktywne iframes (gracz nie otrzymuje obrażeń). NavMesh odłączany — transform przesuwany bezpośrednio. Po zakończeniu: NavMesh.SamplePosition w promieniu 2 m przywraca gracza na siatkę.

Obrót gracza (MOV-003)

Płynny obrót przez Quaternion.Slerp z prędkością 15°/s. Podczas uniku i gdy gracz ma CurrentTarget — obrót w stronę celu.

Kamera (CAM-001 / CAM-003)

Główna kamera izometryczna bez Cinemachine (CameraController): śledzi gracza przez Lerp, zoom scrollem myszy. CameraZoom (Cinemachine) zachowany dla cutscen i Timeline.

OcclusionFader (komponent na Main Camera): ukrywa ściany budynków zasłaniające gracza. Trzy filtry: wysokość Y (tylko obiekty wyżej niż hideAbovePlayerY) + odległość XZ (w promieniu occlusionRadiusXZ) + kierunek (dot product — tylko ściany po stronie kamery). Wyłącza zarówno Renderer jak i Collider — gracz może klikać przez ukrytą ścianę. Wymaga warstwy Buildings w Culling Mask kamery.

Wzory obliczeniowe

MaxHp = baseMaxHp + (hpPerLevel × (level − 1)) + bonusMaxHp + skillBonusMaxHp TotalDamage = baseDamage + (damagePerLevel × (level − 1)) + bonusDamage + skillBonusDamage TotalArmor = Clamp(baseArmor + bonusArmor + skillBonusArmor, 0, 0.75) // max 75% TotalAttackSpeed= baseAttackSpeed + bonusAttackSpeed + skillBonusAttackSpeed TotalCritChance = Clamp01(baseCritChance + bonusCritChance + skillBonusCritChance) TotalMoveSpeed = moveSpeed + bonusMoveSpeed + skillBonusMoveSpeed Level up — HP skaluje się proporcjonalnie: currentHp = (currentHp / oldMaxHp) × newMaxHp

⚔️ System walki

Walka opiera się na kliknięciu na wroga — gracz automatycznie podchodzi i atakuje w zasięgu (1,5 m). Mechanizm ataku kontrolowany jest przez Animation Events w Animatorze. Warunek: canAttack == true && IsInAttackRange && CurrentTarget != null.

Przebieg ataku (GDD-CMB-001)

TriggerAttack() → canAttack = false, trigger "Attack" ↓ Animation Event OnAttackHit() — klatka uderzenia → ApplyDamage() buduje DamageInfo (GDD-CMB-002, GDD-CMB-005) → target.TakeDamage(DamageInfo) [przez IDamageable] ↓ Animation Event OnAttackEnd() — koniec animacji → canAttack = true, ResetTrigger("Attack")

Obliczanie obrażeń (GDD-CMB-002)

outgoing = Round(TotalDamage × (isCritical ? critMultiplier : 1)) TotalDamage = baseDamage + damagePerLevel×(level−1) + bonusDamage + skillBonusDamage isCritical = RollCrit() [prawdopodobieństwo TotalCritChance] critMultiplier = 2×

Zaokrąglenie: Mathf.Round do 0 miejsc po przecinku. Po stronie nadawcy brak limitu dolnego — minimalną stratę 1 HP stosuje odbiorca.

Odbiór obrażeń przez gracza (GDD-CMB-006)

  1. Jeśli IsInvincible == true (iframes) → 0 obrażeń, brak zdarzeń
  2. Redukcja pancerzem: reduced = Round(info.value × (1 − TotalArmor), 1 m.p.p.)
  3. Limit dolny: reduced = max(reduced, 1) — minimalna strata 1 HP
  4. currentHp = max(currentHp − reduced, 0)
  5. Publikuje OnPlayerDamaged; jeśli HP = 0 → publikuje OnPlayerDied

Fallback timer (GDD-CMB-003)

Gdy brak Animatora lub Animation Events (np. w testach), PlayerCombat używa fallback timera: fallbackDuration = 1 / max(TotalAttackSpeed, 0,1) s — atak działa bez animacji.

🐀 Wrogowie (AI)

EnemyData — ScriptableObject

Każdy typ wroga to osobny asset EnemyData (menu: Assets → Create → Ratocalypse → Enemy Data). Pola: maxHp, moveSpeed, patrolSpeed, patrolRadius, detectRange, losePlayerRange, alertDelay, attackRange, attackDamage, attackCooldown, stunDuration, xpReward.

FSM — stany AI

PATROL → (gracz w detectRange) → ALERT → (alertDelay minął) → CHASE → (w attackRange) → ATTACK ↑ ↓ ↓ (gracz > losePlayerRange) (HP ≤ 0) (ApplyStun) PATROL ← DEAD STUNNED → CHASE
  • PATROL:Waypoints w pętli lub losowy punkt w promieniu patrolRadius (do 8 prób na NavMesh). Prędkość: patrolSpeed
  • ALERT:Odległość do gracza ≤ detectRange — stoi nieruchomo przez alertDelay s
  • CHASE:NavMeshAgent aktualizuje trasę co klatkę; brak drogi → stoi. Wyjście: odległość > losePlayerRange → PATROL
  • ATTACK:Odległość ≤ attackRange; Animation Event OnAttackHit() → playerDamageable.TakeDamage(attackDamage); cooldown: attackCooldown
  • STUNNED:ApplyStun(duration) wywołane przez PlayerCombat — NavMesh zatrzymany, brak ataku przez duration s
  • DEAD:HP ≤ 0 → NavMesh i Collider wyłączone → Animator trigger "Dead" → publikuje OnEnemyDied { xpReward } → Destroy po 3 s

🎒 Ekwipunek i przedmioty

ItemData — ScriptableObject

Każdy typ przedmiotu to osobny asset (Assets → Create → Ratocalypse → Item). Pole itemId (format: item_<typ>_<nazwa>) — trwały unikalny identyfikator, klucz w zapisie gry. Puste itemId → Debug.LogWarning w edytorze.

Typy przedmiotów i sloty

Broń (Weapon)

Fists / OneHanded / TwoHanded / Ranged. Slot MainHand. Broń dwuręczna (isTwoHanded) automatycznie zwalnia OffHand.

Tarcza (Shield)

Slot OffHand. Niedostępny gdy MainHand trzyma broń dwuręczną.

Zbroja (Helmet / Chest / Legs / Boots)

Cztery sloty na sylwetce. Każdy przyjmuje jeden typ.

Konsumable (Consumable)

Tylko w plecaku. Kliknięcie w UI: Heal(healAmount) + RestoreStamina(staminaRestore) → usuwa z plecaka.

Przeliczanie bonusów (INV-004)

Po każdym Equip() lub Unequip(): stats.ResetBonuses() (zeruje bonus*, nie dotyka skillBonus*), następnie suma bonusów z założonych przedmiotów aplikowana do PlayerStats.

Podnoszenie z ziemi (ItemPickup)

Przedmioty w scenie: GameObject z ItemPickup na warstwie Interactable. Gracz klika → podchodzi → Interact() → InventorySystem.AddToBag() (jeśli plecak pełny: false) → obiekt znika ze sceny.

UI Ekwipunku

Otwierany klawiszem I. BagGrid: 20 slotów. Sylwetka: 6 slotów. Odświeżanie tylko gdy panel otwarty (OnInventoryChanged, OnItemEquipped, OnItemUnequipped). Kliknięcie w plecaku → EquipFromBag() (lub UseConsumable() dla konsumabla). Kliknięcie w slocie ekwipunku → Unequip(slot). Panel I i panel C (Skill Tree) wzajemnie się zamykają.

⭐ Doświadczenie i poziomy

XPSystem nasłuchuje dwóch zdarzeń EventBus i przyznaje XP:

  • OnEnemyDied:XP = EnemyData.xpReward zabitego wroga (domyślnie 25 XP dla Szczura zwykłego)
  • OnQuestCompleted:XP = QuestData.xpReward ukończonej misji

Wzór progu XP na level up

XP_required(level) = xpForLevel2 × (1.4 ^ (level − 1)) Przykłady (xpForLevel2 = 100): Poziom 1→2: 100 XP Poziom 2→3: 140 XP Poziom 3→4: 196 XP Poziom 4→5: 274 XP Maksymalny poziom: 20

Efekty awansu

  • HP skaluje się proporcjonalnie:currentHp = (currentHp / oldMaxHp) × newMaxHp
  • Punkt umiejętności:availableSkillPoints++
  • Zdarzenie:OnPlayerLevelUp { newLevel, remainingPoints }

Regeneracja HP

PlayerHealthComponent.Update() co klatkę dodaje stats.TotalHpRegen × deltaTime HP. Źródło: skillBonusHpRegen (Survivor T2: +1,5 HP/s). Jeśli TotalHpRegen == 0 — brak regeneracji.

XPBarUI

Poziomy pasek XP w HUD. Wartość: currentXP / xpToNextLevel. Subskrybuje OnPlayerXPGained. Po awansie aktywuje GameObject "LEVEL UP!" na levelUpDisplayTime sekund.

📜 System questów

QuestData — ScriptableObject

Pola: questId (string, unikalny), questName, description, targetItem (ItemData), xpReward (int), searchAreaRadius (float, m).

Przepływ questa

Przeliczanie pozycji (MIN-002)

uvX = (worldPos.x − worldMin.x) / (worldMax.x − worldMin.x) uvY = (worldPos.z − worldMin.y) / (worldMax.y − worldMin.y)

Obszar questa (MIN-003)

Po OnQuestAccepted — zielony półprzezroczysty okrąg (QuestAreaCircle, ~30% alpha) wskazujący obszar poszukiwań. Rozmiar okręgu przeliczany z searchAreaRadius (m) do pikseli UV minimapy wg worldMin/worldMax. Znika po OnQuestCompleted.

MinimapMarker — lekki komponent na każdym obiekcie świata. Rejestruje się w MinimapController przez OnEnable/OnDisable. Gdy wróg ginie i jego GameObject jest niszczony, marker automatycznie znika z mapy.

🖥️ Interfejs użytkownika (HUD)

HUD

Pasek HP

Pionowy Image.fillAmount (HealthFull nad HealthEmpty). Wartość: currentHp / maxHp. Subskrybuje OnPlayerDamaged, OnPlayerHealed. Inicjalizacja w Start().

Pasek Staminy

Poziomy Image.fillAmount. Wartość: currentStamina / maxStamina. Subskrybuje OnPlayerStaminaChanged.

Pasek XP

Poziomy fill + tekst poziomu. Wartość: currentXP / xpToNextLevel. Subskrybuje OnPlayerXPGained. Level up: aktywuje "LEVEL UP!" na levelUpDisplayTime s.

🔊 Audio (FMOD)

Całe audio w grze przechodzi przez FMOD Studio — Unity's AudioSource nie jest używany. Dostęp do zdarzeń FMOD przez GameManager.FMODEvents (przypisany w Inspektorze).

  • FMODEvents:ScriptableObject z referencjami do wszystkich zdarzeń FMOD (EventReference). Nie używać Resources.Load.
  • AudioManager:Singleton opakowujący FMODUnity.RuntimeManager. Metody: PlayOneShot(ref, pos) (3D), PlayOneShot(ref) (2D), CreateInstance(ref) (pętle — wymaga Release), CreateAndAttach(ref, transform), PlayMusic(ref) (auto-stop + fadeout).
  • StudioEventEmitter:Dla dźwięków przestrzennych (wrogowie, otoczenie) — komponent bezpośrednio na GameObject.
